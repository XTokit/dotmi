# 发布前检查

## 必须完成

- GPL-3.0-only 已由项目所有者确认，`LICENSE` 已加入；发布前继续核对图标和引用代码的来源与授权。
- 对将进入 Git 的文件清单执行隐私、密钥与大文件检查；不上传 `交付/`、个人索引或私人截图。
- 在干净目录重新构建，执行核心与桌面集成验证；核查首次启动、权限不足、受排除目录、窗口重新打开和旧索引升级。
- README 仅列明实际验证过的系统与架构；跨架构编译不能替代 Intel 实机测试。
- 用合成文件生成截图，复查路径、窗口标题与文件名没有私人信息。
- GitHub CLI 已登录，确认目标账号、仓库名称及公开范围后再建仓推送。

## 源码发布

GitHub 仓库只提交源码、图标源文件、说明、测试与 CI。先使用预览版说明，不把目前本地使用版本号理解为经过全面兼容性验证的稳定版本。自动 CI 通过并不代表已测试完整桌面权限与预览场景。

## 安装包发布

当前构建使用临时本地签名；不要把该包描述为已公证的正式发行版。正式外部分发需另外准备 Developer ID 签名与 Apple 公证，并在开启默认安全设置的干净 Mac 验证下载、启动、授权与升级体验。签名证书与账号凭据只存于本机安全存储或 GitHub Secrets，不进入仓库。

如发布 ZIP/安装包，请放入 GitHub Releases，不提交到 Git 历史。保持 ZIP 内 `点觅.app` 固定名称。对外文件命名使用项目所有者的日期版本规则，并同时提供 SHA-256 校验值、系统要求、架构和已知限制。

## 优先优化顺序

1. 新用户首次启动、授权与搜不到文件时的反馈。
2. 静置、启动补录和大量文件变化时的 CPU、内存、磁盘与响应测量。
3. 区分“隐藏展示”“未索引”“无法访问”“位置离线”，避免把整台 Mac 当作绝对全覆盖。
4. 干净机器安装与覆盖升级；补充 Intel 实机验证后再宣称支持。

拼音、全文/OCR、复杂排序、额外主题与自动更新可在基础体验稳定后逐步加入。
